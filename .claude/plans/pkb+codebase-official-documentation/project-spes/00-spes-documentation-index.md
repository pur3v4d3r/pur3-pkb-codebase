## 📚 Documentation Suite Overview

### 1. Master Operations Manual
**File:** [[01-spes-master-operations-manual]]

> [!what-this-does] Complete System Reference
> The **authoritative, comprehensive guide** to the entire SPES system. Contains:
> - System architecture and three-pillar design
> - Complete folder structure
> - Full metadata schema with controlled vocabularies
> - Daily operations workflows
> - Dataview queries and dashboards
> - LLM integration protocols

**Audience:** Everyone (human and AI)
**Length:** ~40+ pages equivalent
**When to Use:** When you need deep understanding or reference details

### 2. Quick Start Guide
**File:** [[02-spes-quick-start-guide]]

> [!what-this-does] Get Operational in 15 Minutes
> **Fastest path to productivity.** Contains:
> - Essential concepts only
> - First prompt creation walkthrough
> - Component library basics
> - Quick testing workflow
> - Copy-paste templates

**Audience:** New users, quick refreshers
**Length:** ~10 pages equivalent
**When to Use:** First day, or when you just need to get something done fast

### 3. LLM Integration Protocol
**File:** [[03-llm-integration-protocol]]

> [!what-this-does] AI Assistant Operating Instructions
> **How Claude and other LLMs should work within SPES.** Contains:
> - SPES Librarian role definition
> - Decision frameworks (with flowcharts)
> - Core operations (create, search, recommend, test, maintain)
> - Output format standards
> - Interaction patterns
> - Quality assurance checklists

**Audience:** AI assistants (Claude, etc.)
**Length:** ~25 pages equivalent
**When to Use:** When operating as AI within the system

---

### 4. Component Library Reference
**File:** [[04-component-library-reference]]

> [!what-this-does] Complete Guide to Prompt Building Blocks
> **Everything about components.** Contains:
> - Library architecture and philosophy
> - All component types (personas, instructions, constraints, formats, context)
> - Example components for each type
> - Component creation workflow
> - Discovery and search strategies
> - Maintenance lifecycle

**Audience:** Component creators and users
**Length:** ~30 pages equivalent
**When to Use:** When creating, finding, or maintaining components

---

### 5. Troubleshooting & Diagnostics Guide
**File:** [[05-troubleshooting-diagnostics-guide]]

> [!what-this-does] Problem Solving & System Maintenance
> **Fix issues and keep the system healthy.** Contains:
> - Quick diagnostics checklist
> - Issue catalog (Dataview, metadata, components, templates, links)
> - Maintenance procedures (daily, weekly, monthly)
> - Diagnostic queries library
> - Emergency recovery procedures

**Audience:** System maintainers, troubleshooters
**Length:** ~25 pages equivalent
**When to Use:** When something's broken or during maintenance

## 📝 Documentation Standards

All documentation in this suite follows these standards:

**Structure:**
- YAML frontmatter with full metadata
- Abstract callout at top explaining purpose
- Logical section hierarchy
- Wiki-links for all key concepts
- Expansion topics section at bottom

**Formatting:**
- Callouts for semantic structure
- Tables for comparative information
- Code blocks with language specification
- Prose-dominant (minimal bullet lists)

**Maintenance:**
- Version tracked in frontmatter
- Modified date updated on changes
- Related documents cross-linked
