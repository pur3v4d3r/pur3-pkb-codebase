# PKB Extractor — README

## What This Script Does

`pkb_extractor.py` reads your Obsidian Markdown files (especially Claude-generated reports) and pulls out every meaningful structural element — callouts, wiki-links, inline definitions, tags, headings, code blocks, tables, color-coded spans, and more. For each file it processes, it creates **two outputs**:

1. A **JSON file** containing all extracted data in machine-readable format (for Dataview, scripts, or future analysis).
2. A **Markdown report** you can open directly in Obsidian, complete with YAML frontmatter, callouts, wiki-links, and summary tables.

The script handles all four of your report types (Foundational, Focused Analysis, First Principles, Socratic Dialogue) and any other Obsidian Markdown file.

---

## Quick Start

```bash
# Make sure you have Python 3.8+ installed
# No extra packages required — uses only the Python standard library

# Process a single report:
python pkb_extractor.py --input "D:\10_pur3v4d3r's-vault\999-report-orginizing\999-foundational-report-genrator\metacognition-and-critical-thinking-foundational-report-2026-03-05.md"

# Process an entire folder of reports:
python pkb_extractor.py --input "D:\10_pur3v4d3r's-vault\999-report-orginizing\999-foundational-report-genrator" --output "D:\10_pur3v4d3r's-vault\00-inbox\01-reports"

# Process multiple folders recursively:
python pkb_extractor.py --input "D:\10_pur3v4d3r's-vault\999-report-orginizing" --recursive --output "D:\10_pur3v4d3r's-vault\999-report-orginizing\_extractor-output"

# Get help:
python pkb_extractor.py --help
```

> **Optional Enhancement**: Install `pyyaml` for better YAML parsing of complex frontmatter:
> ```bash
> pip install pyyaml
> ```
> The script works without it (using built-in regex parsing), but PyYAML handles nested YAML more reliably.

## What You'll Get

For each Markdown file processed, the script creates two files in your output folder:

| File | Format | Purpose |
|------|--------|---------|
| `{filename}_extracted.json` | JSON | Machine-readable structured data for imports, Dataview, and analysis |
| `{filename}_report.md` | Markdown | Human-readable report for review in Obsidian with full PKB metadata |

## What Gets Extracted

| # | Element Type | Description | Example |
|---|-------------|-------------|---------|
| 1 | **YAML Frontmatter** | All metadata fields from the `---` block at the top of the file | `title`, `tags`, `domain`, `key-frameworks` |
| 2 | **Callouts** | All `> [!TYPE]` blocks — definitions, insights, warnings, etc. | `> [!definition] Metacognition` |
| 3 | **Wiki-Links** | All `[[Target]]`, `[[Target\|Display]]`, `[[Target#Section]]` references | `[[Cognitive Load Theory]]` |
| 4 | **Inline Fields** | Dataview `[**Name**:: Value]` and `Name:: Value` fields | `[**Self-Regulation**:: The ability to...]` |
| 5 | **Definitions** | Bold-formatted inline definitions specifically | `[**Metacognition**:: Thinking about thinking]` |
| 6 | **Tags** | All `#tag` references including hierarchical `#parent/child` | `#cognitive-psychology/metacognition` |
| 7 | **Headings** | All heading levels with document outline tree | `## Core Concepts` |
| 8 | **Code Blocks** | Fenced code blocks with language identifier | ` ```python ... ``` ` |
| 9 | **Tables** | Full table data — headers, alignment, all rows | Markdown tables |
| 10 | **External Links** | `[text](URL)` links and bare URLs | `[Anthropic](https://anthropic.com)` |
| 11 | **Embeds** | Obsidian embeds `![[Target]]` for notes and images | `![[diagram.png]]` |
| 12 | **Block References** | `^block-id` definitions and `[[note^block]]` references | `^metacognition-def` |
| 13 | **Mermaid Diagrams** | Mermaid diagram code blocks extracted separately | ` ```mermaid ... ``` ` |
| 14 | **Footnotes** | `[^ref]: text` definitions and `[^ref]` usage | `[^1]: See Smith 2024` |
| 15 | **Color Spans** | Semantic `<span style='color: #HEX;'>` elements | Gold = key concept, Green = verified principle |
| 16 | **Lists** | Ordered and unordered list items with nesting levels | `1. First item`, `- Bullet item` |
| 17 | **HTML Comments** | `<!-- comment -->` blocks (often generation metadata) | `<!-- Generated by Claude -->` |

## Understanding the Output

### The JSON File

The JSON output follows a structured schema with these top-level sections:

```json
{
  "extraction_metadata": {
    "script_name": "pkb_extractor.py",
    "extraction_timestamp": "2026-03-12T14:30:00",
    "source_file": "my-report.md",
    "processing_time_seconds": 0.42
  },
  "document_metadata": {
    "frontmatter": { "...all YAML fields..." },
    "word_count": 8423,
    "character_count": 52031,
    "line_count": 1204
  },
  "extraction_summary": {
    "total_items_extracted": 247,
    "by_type": {
      "callouts": 18,
      "wiki_links": 62,
      "...": "..."
    }
  },
  "document_outline": [ "...hierarchical heading tree..." ],
  "extracted_items": {
    "callouts": [ "...array of callout objects..." ],
    "wiki_links": [ "...array of wiki-link objects..." ],
    "...": "...one array per extraction type..."
  },
  "knowledge_graph": {
    "unique_wiki_link_targets": [ "...all distinct notes referenced..." ],
    "frontmatter_relationships": { "...relationship categories..." }
  }
}
```

### The Markdown Report

The Markdown report contains these sections:

1. **YAML Frontmatter** — PKB-conformant metadata header
2. **Document Overview** — Source file stats, word count, document outline
3. **Extraction Summary** — Table of counts by element type
4. **Callouts** — Grouped by type, with full body text reproduced
5. **Wiki-Links** — Unique targets list + full occurrence table with sections
6. **Definitions** — All `[**Term**:: Definition]` entries
7. **Inline Fields** — All Dataview fields in a table
8. **Tags** — Unique tags, hierarchical grouping
9. **Code Blocks** — Each block with language and line numbers
10. **Tables** — Reproduced as Markdown tables
11. **External Links** — URL table
12. **Embeds** — Embed targets table
13. **Mermaid Diagrams** — Reproduced diagram blocks
14. **Color Spans** — Semantic color analysis table
15. **Knowledge Graph Analysis** — Unique targets + frontmatter relationships
16. **Raw Data Reference** — Pointer to the companion JSON file

## Importing into Obsidian

1. Copy the `_report.md` files into your Obsidian vault (e.g., `00-inbox/01-reports/`).
2. Open them in Obsidian — they'll have full YAML metadata, wiki-links, and callouts.
3. The JSON files can be stored anywhere for programmatic use or Dataview queries.

## Troubleshooting

| Problem | Solution |
|---------|----------|
| `"File not found"` error | Check the path — use quotes if it has spaces |
| `"Python not found"` | Install Python 3.8+ from [python.org](https://python.org) |
| Empty output / 0 items | The file may have no extractable items, or it may not be valid Markdown |
| Encoding error | Re-save your Markdown file as UTF-8 (most editors can do this) |
| YAML parsing issues | Install `pyyaml`: `pip install pyyaml` for better YAML handling |
| Callouts not detected | Ensure callouts use the `> [!TYPE]` format with a space after `>` |

## Customizing the Script

### Adding New Callout Types

Open `pkb_extractor.py` and find the `KNOWN_CALLOUT_TYPES` set near the top of the file. Add your custom type:

```python
KNOWN_CALLOUT_TYPES = {
    # ... existing types ...
    "my-custom-type",  # Add your custom callout type here
}
```

### Adding New Semantic Colors

Find the `SEMANTIC_COLORS` dict and add your color:

```python
SEMANTIC_COLORS = {
    # ... existing colors ...
    "#YOUR_HEX": "Your Role Description",
}
```

### Disabling an Extractor

In the `process_single_file()` function, comment out the extractor you don't need:

```python
# callouts = extract_callouts(content, source_file)
callouts = []  # Disabled
```

### Changing What Appears in Reports

In the `build_markdown_report()` function, each section is clearly labeled with comment blocks (`# SECTION: Callouts`, etc.). You can remove, reorder, or modify any section.

## Technical Details

- **Python Version**: 3.8+
- **Dependencies**: None required (standard library only). Optional: `pyyaml`.
- **Encoding**: UTF-8 (with Latin-1 fallback)
- **Processing**: Sequential, single-threaded
- **Pattern Matching**: Compiled regex patterns for performance
