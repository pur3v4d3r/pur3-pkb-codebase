# Batch: B01-05 Multimodal Prompting

## Vision-Language Model Prompting

- secondary_domains: [prompt-engineering, computer-vision, multimodal-learning]
- aliases: [VLM prompting, vision-language prompting, multimodal prompt design, GPT-4V prompting]
- broader: [prompt-engineering, multimodal-ai]
- narrower: [image-captioning-prompts, visual-chain-of-thought, document-understanding-prompting]
- related: [image-captioning-prompts, visual-chain-of-thought, multimodal-few-shot-prompting, document-understanding-prompting, chart-and-table-prompting]
- prerequisites: [prompt-engineering, vision-language-models, transformer-architecture]
- confidence: high

**definition**: Vision-language model (VLM) prompting encompasses the prompt engineering techniques specific to models that accept both image and text inputs, such as GPT-4V, Claude 3.x, LLaVA, and Gemini. Unlike text-only prompting, VLM prompting must account for the relationship between visual and textual modalities — how to reference image regions, how to structure questions about visual content, when to use chain-of-thought for visual reasoning, how to handle multiple images, and how to integrate visual context with textual instructions. The design space includes image placement within the prompt, verbosity of textual grounding, reference styles (spatial, descriptive, bounding-box), and the specificity of visual questions.

**key_claim**: The principles of effective text prompting transfer substantially to VLM prompting but require visual-specific extensions — specificity, chain-of-thought, and role assignment all improve VLM performance, but VLM prompts additionally benefit from explicit visual grounding instructions that direct the model's attention to specific image regions, and from structured output requests that prevent the model from producing unverifiable visual descriptions.

**warning**: VLMs have inconsistent visual grounding capabilities — they may produce confident-sounding descriptions of image details that are not actually present in the image, and spatial reasoning (left/right, above/below) is particularly unreliable in many current VLMs; prompts that require precise spatial reasoning or fine-grained visual detail should include explicit uncertainty elicitation to surface the model's uncertainty about visual claims.

## Image Captioning Prompts

- secondary_domains: [prompt-engineering, computer-vision, multimodal-ai]
- aliases: [caption generation prompts, image description prompting, visual description prompt design]
- broader: [vision-language-model-prompting, multimodal-ai]
- narrower: []
- related: [vision-language-model-prompting, visual-chain-of-thought, multimodal-few-shot-prompting, document-understanding-prompting]
- prerequisites: [vision-language-models, prompt-engineering]
- confidence: high

**definition**: Image captioning prompts are structured text instructions given to vision-language models to elicit descriptions of image content, ranging from brief factual captions to detailed contextual analyses. Prompt design for image captioning involves specifying the desired caption length and verbosity, the level of abstraction (literal description vs. semantic interpretation), the target audience (expert domain language vs. general audience), the aspects to emphasise (objects, actions, spatial relationships, mood, context), and the output format (one sentence, structured description, metadata tags). Captioning prompts are used in content indexing, accessibility tools, dataset annotation, and multimodal retrieval pipelines.

**key_claim**: The specificity of image captioning prompts has a larger effect on caption quality than model size in many settings — a precisely specified captioning prompt on a mid-tier VLM often produces more useful, application-appropriate captions than a generic "describe this image" prompt on a frontier model, because the model lacks the ability to infer the user's captioning requirements without explicit instruction.

**warning**: Image captioning prompts that request high-level semantic interpretation (e.g., "what emotion does this image convey?") elicit responses that reflect training data biases rather than the literal image content — VLMs trained on human-captioned datasets inherit culturally specific interpretive conventions, making cultural neutrality a significant challenge for cross-cultural captioning applications.

## Visual Chain-of-Thought

- secondary_domains: [prompt-engineering, computer-vision, reasoning]
- aliases: [visual CoT, vision-language chain of thought, VLM chain of thought]
- broader: [chain-of-thought-prompting, vision-language-model-prompting]
- narrower: []
- related: [vision-language-model-prompting, multimodal-few-shot-prompting, chain-of-thought-prompting, image-captioning-prompts]
- prerequisites: [chain-of-thought-prompting, vision-language-models, visual-reasoning]
- confidence: high

**definition**: Visual chain-of-thought (Visual CoT) is the application of chain-of-thought prompting to vision-language models, eliciting explicit intermediate reasoning steps that describe visual observations before drawing conclusions or answering questions. A visual CoT prompt asks the model to first describe relevant visual elements, then reason about their relationships, then derive an answer — mirroring the structure of standard CoT but with an additional visual grounding step where the model translates visual information into text-based reasoning chains. This approach improves performance on visual reasoning tasks including mathematical problem solving from diagrams, scientific question answering from charts, and scene understanding.

**key_claim**: Visual CoT improves VLM performance on reasoning tasks by decoupling visual perception from logical inference — the explicit visual description step forces the model to commit to a factual visual interpretation before drawing conclusions, reducing the tendency to produce plausible-sounding but visually unsupported reasoning chains; the intermediate text description also provides a checkable intermediate state that helps surface visual perception errors.

**warning**: Visual CoT inherits all failure modes of text-only CoT — including incorrect reasoning chains that produce a confident wrong answer — with the additional risk that the visual description step may itself contain errors that then propagate into the reasoning chain; a confident but wrong visual description is especially pernicious because it grounds subsequent text reasoning in a false factual premise.

## Multimodal Few-Shot Prompting

- secondary_domains: [prompt-engineering, in-context-learning, multimodal-ai]
- aliases: [multimodal in-context learning, VLM few-shot, image-text few-shot prompting]
- broader: [few-shot-prompting, vision-language-model-prompting]
- narrower: []
- related: [vision-language-model-prompting, visual-chain-of-thought, in-context-learning, few-shot-prompting]
- prerequisites: [few-shot-prompting, vision-language-models, in-context-learning]
- confidence: high

**definition**: Multimodal few-shot prompting is the technique of providing VLMs with example (image, text) input-output pairs within the prompt context to demonstrate the desired task format and output structure before presenting the query image. By showing the model how to process image inputs and format outputs — with examples that pair images with desired responses — multimodal few-shot prompting leverages in-context learning to adapt VLM behaviour without fine-tuning. Example formats include image-captioning demonstrations, visual question answering examples, image classification examples, and visual reasoning chains.

**key_claim**: Multimodal few-shot prompting is more sensitive to example selection than text-only few-shot prompting because image examples must match the query in both task type and visual domain — an example from a different visual domain (e.g., using a photograph as an example for a medical imaging task) provides weaker task signal than domain-matched examples, making strategic example selection even more critical in the multimodal setting.

**warning**: Many VLMs have context length limitations that significantly constrain the number of image-text pairs that can be included in a few-shot prompt — each image consumes a large number of tokens (often 500–1000+ for high-resolution images), meaning that even moderate few-shot settings (k=5) may exceed the effective context window and cause degraded performance on the query itself.

## Audio Language Model Prompting

- secondary_domains: [prompt-engineering, speech-processing, multimodal-ai]
- aliases: [audio LM prompting, speech-language model prompting, audio-text prompting]
- broader: [multimodal-ai, vision-language-model-prompting]
- narrower: []
- related: [vision-language-model-prompting, multimodal-few-shot-prompting, speech-recognition]
- prerequisites: [speech-language-models, prompt-engineering, audio-processing]
- confidence: high

**definition**: Audio language model prompting refers to the techniques for structuring inputs and eliciting outputs from models that process audio signals alongside text, such as Gemini 1.5's audio capabilities, AudioPaLM, and emerging speech-native LLMs. Unlike text transcription pipelines (ASR → text LLM), audio LM prompting allows the model to reason about prosody, tone, speaker identity, environmental context, and acoustic events in addition to the linguistic content, enabling richer audio understanding tasks such as sentiment analysis from speech, speaker diarisation, audio scene understanding, and emotion recognition from voice.

**key_claim**: The key advantage of audio language model prompting over cascaded ASR+text pipelines is the preservation of supralinguistic features — prosody, speaking rate, tone, and acoustic environment encode information that is lost in transcription, and audio-native models can leverage this information for tasks like sarcasm detection, clinical speech assessment, and call centre sentiment analysis that are significantly harder without the audio signal.

**warning**: Audio language model capabilities are less mature and less uniformly available than vision capabilities in frontier models — prompting conventions, failure modes, and effective prompt structures for audio are less well-studied than for image prompting, and available models show high variability in which audio understanding tasks they handle reliably versus those where they hallucinate confidently.

## Document Understanding Prompting

- secondary_domains: [prompt-engineering, document-ai, computer-vision]
- aliases: [document VLM prompting, visually rich document understanding, layout-aware prompting]
- broader: [vision-language-model-prompting, multimodal-ai]
- narrower: [invoice-extraction-prompting, form-understanding-prompting]
- related: [vision-language-model-prompting, chart-and-table-prompting, structured-output-enforcement, image-captioning-prompts]
- prerequisites: [vision-language-models, document-ai, prompt-engineering]
- confidence: high

**definition**: Document understanding prompting refers to the prompt engineering techniques for vision-language models applied to visually rich documents — PDFs, scanned forms, invoices, receipts, contracts, and academic papers — where the document layout, typography, tables, and visual structure carry semantic meaning that must be interpreted alongside the text content. Effective document understanding prompts must instruct the model on how to handle multi-column layouts, how to interpret table headers and cells, how to extract structured data from free-form layouts, and how to reconcile conflicting information in document headers versus body text. Tasks include information extraction, document classification, question answering over documents, and form completion.

**key_claim**: Document understanding is one of the most practically valuable VLM applications because the volume of unstructured document data in enterprises dwarfs structured data, yet it is also one of the hardest prompt engineering challenges because documents combine multiple modalities (text, layout, tables, images, logos) in patterns that require integrated understanding; the most effective document understanding prompts provide explicit instructions about layout interpretation rather than assuming the model will infer these from context.

**warning**: Document understanding VLMs are particularly prone to hallucination when document text is partially illegible, when small fonts or compressed images reduce text resolution, or when documents contain form fields that are partially filled or have complex conditional logic — the model may infer plausible field values rather than acknowledging that the content is unclear.

## Chart and Table Prompting

- secondary_domains: [prompt-engineering, data-visualisation, multimodal-ai]
- aliases: [chart reasoning prompts, table understanding prompting, data visualisation QA]
- broader: [document-understanding-prompting, vision-language-model-prompting]
- narrower: []
- related: [document-understanding-prompting, visual-chain-of-thought, structured-output-enforcement, vision-language-model-prompting]
- prerequisites: [vision-language-models, data-visualisation, prompt-engineering]
- confidence: high

**definition**: Chart and table prompting refers to the techniques for eliciting accurate analytical and interpretive responses from vision-language models when the input is a data visualisation (bar chart, line graph, scatter plot, pie chart) or tabular data (HTML tables, spreadsheet screenshots, markdown tables). Effective chart and table prompts specify what type of analysis is required (trend identification, value extraction, comparison, statistical summary), instruct the model on how to handle axis labels and units, request explicit numerical extraction before synthesis, and use chain-of-thought to separate data reading from interpretation. These tasks challenge VLMs because they require precise numerical reasoning over visually encoded data.

**key_claim**: Chain-of-thought prompting dramatically improves chart and table understanding performance by forcing the model to separately externalise data extraction (reading values from the visualisation) and data interpretation (drawing conclusions from those values) — without explicit CoT, models tend to produce plausible-sounding but numerically inaccurate interpretations that conflate the two steps, while CoT-prompted models can be evaluated for the quality of each step independently.

**warning**: Chart prompting is particularly susceptible to visual encoding errors — VLMs frequently misread y-axis values, mistake ordinal categories for continuous variables, or misinterpret overlapping visual elements; requesting explicit numerical extractions before any synthesis step and cross-checking extracted numbers against stated axis ranges can partially mitigate these errors, but do not eliminate them for complex or cluttered visualisations.
