# Report Extraction → Permanent Notes Pipeline v2.0

> Automated end-to-end pipeline for extracting knowledge from generated reports, building/updating permanent notes, resolving wiki-links, auditing quality, and committing changes — designed for agentic execution via GitHub Copilot or Claude Code.

---

## Overview

This pipeline transforms **Markdown reports** (generated by Claude/GPT) into a fully connected library of **Obsidian permanent notes** — complete with YAML frontmatter, wiki-links, callout-based definitions, cross-references, and quality auditing.

### Pipeline Stages

| # | Stage | Script(s) | What It Does |
|---|-------|-----------|-------------|
| 0 | **Pre-Flight** | `pipeline_v2.py` | Validate paths, dependencies, count existing notes |
| 1 | **Extract** | `pkb_extractor.py` | Parse reports → JSON + MD extraction files |
| 2 | **Build Notes** | `pipeline.py` (scan → match → update → create) | Create/update permanent notes from extractions |
| 2b | **Dedicated Notes** | `dedicated_notes_builder.py` | Build 4 aggregate index notes (definitions, references, connections, expansions) |
| 3 | **Generate Stubs** | `generate_stubs.py` | Create stub notes for frequently-referenced missing concepts |
| 4 | **Resolve Report Links** | `rewrite_report_wikilinks.py` | Rewrite wiki-links in reports to pipe syntax |
| 5 | **Normalise Links** | `normalise_wikilinks.py` | Fix space-separated wiki-links → kebab-case |
| 6 | **Audit** | `audit_notes.py` | Measure resolution rate, orphans, connectivity |
| 7 | **Index** | `vault_indexer.py` | Update the permanent notes index document |
| 8 | **Report** | `pipeline_v2.py` | Generate JSON + Markdown change report |
| 9 | **Commit** | `pipeline_v2.py` | Git commit with descriptive message |

### Data Flow

  --execute              Apply changes (default: dry run)
  --auto-commit          Git commit all changes when done

## Configuration

All configuration is centralized in `config.py`:

- **Paths**: Vault root, permanent notes dir, extraction batch dirs
- **Matching**: Fuzzy match threshold (0.85), max candidates (5)
- **Note Generation**: Which callout types generate notes (`definition`, `original-synthesis`)
- **Domain Mapping**: 30+ domain string → slug mappings
- **Content Limits**: Max evidence (3), insights (2), practices (2), warnings (2) per note
- **Dedicated Notes**: `DEDICATED_NOTE_FILES` (output filenames), `DEDICATED_*_CALLOUTS` (callout type lists for each aggregate note)

To add new extraction batches, append to the `EXTRACTION_BATCHES` list in `config.py`.

## Troubleshooting

### Common Issues

| Problem | Solution |
|---------|----------|
| `ModuleNotFoundError: rich` | Activate venv: `source ".venv/Scripts/activate"` |
| `UnicodeEncodeError` on Windows | Scripts handle this with UTF-8 wrappers; if persisting, set `PYTHONIOENCODING=utf-8` |
| Pipeline shows 0 candidates | Check that `EXTRACTION_BATCHES` in `config.py` includes your batch directories |
| Stubs not generating | Lower `--min-stub-refs` threshold (default: 3) |
| Wiki-link resolution low | Run stages 4+5 (report link rewriting + normalisation) |
| Git commit fails | Ensure no uncommitted merge conflicts; check `git status` |

### How to Add New Report Sources

1. **Extract reports** to a new batch directory:
   ```bash
   python 99-scripts/pkb_extractor.py --input "path/to/new/reports" \
     --output "999-report-organizing/_extractor-output/YYYY-MM-DD-batch-name" -r
   ```

2. **Add the batch** to `config.py`:
   ```python
   EXTRACTION_BATCHES = [
       # ... existing batches ...
       EXTRACTOR_OUTPUT_ROOT / "YYYY-MM-DD-batch-name",
   ]
   ```

3. **Add report folder** to `rewrite_report_wikilinks.py` `REPORT_FOLDERS` list (if wiki-links in reports need resolution)

4. **Run the pipeline**:
   ```bash
   python 99-scripts/report-extraction-to-permanent-notes-building/pipeline_v2.py --execute --auto-commit --verbose
   ```

## Safety

- **Dry-run by default** — all scripts default to showing what WOULD change without modifying any files
- **Idempotent** — running the pipeline again won't create duplicates (deduplication is built into every stage)
- **Additive only** — the note updater only ADDS content (new evidence, insights, etc.), never removes existing content
- **Git integration** — auto-commit creates a detailed, reversible record of all changes
- **Stage isolation** — each stage can be run independently, allowing targeted re-runs after fixing issues
