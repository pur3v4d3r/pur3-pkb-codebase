# Tools as Cognitive Scaffolding, Not Cognitive Replacement

> [!definition] Tools as Cognitive Scaffolding, Not Cognitive Replacement
> Tools as cognitive scaffolding refer to using technology to support learning processes that a user is developing but cannot yet perform independently, with the expectation that these tools will eventually become unnecessary as the user internalizes the learned skills.

## Reflections

> [!claude-insight] Tools as Cognitive Scaffolding, Not Cognitive Replacement
> The most consequential design insight that emerges from the full seven-problem analysis concerns the proper role of PKM tools. Tools — Obsidian, Anki, Dataview, Templater, and their equivalents — should function as *cognitive scaffolding*: structures that support cognitive processes the learner is developing but cannot yet perform independently. Scaffolding, in Vygotskian terms, operates within the [[zone-of-proximal-development|zone of proximal development]] — it supports performance that the learner could not achieve alone, with the expectation that the learner will eventually internalize the capacity the scaffold supports. A spaced repetition system scaffolds retrieval scheduling until the learner develops sufficient metacognitive awareness to self-schedule reviews. A linking interface scaffolds associative thinking until the learner's own schema networks become dense enough to generate connections spontaneously. A template scaffolds elaborative encoding until the learner's note-taking practices internalize the elaboration habit. The danger arises when tools become *cognitive replacements* rather than cognitive scaffolds — when the learner delegates not just execution but understanding to the system, such that removing the tool would leave the learner less capable than before. A system that replaces rather than scaffolds is a dependency, not a tool.
> *— [[pkb-pkm-planning-and-cognitive-science-foundational-report-2026-04-18]]*
