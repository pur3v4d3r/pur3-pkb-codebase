## Core Explanation

> [!evidence] Schema-Fidelity in API Design
> **Structural Principle:** The more accurately a software interface externalizes the conceptual schema of its domain (rather than merely the historical accidents of its implementation), the lower the cognitive load on developers integrating with it, and the more generatively the interface supports future use patterns the designer did not anticipate.
>
> **Concrete Application:** "Domain-Driven Design" (Evans, 2003) is, in schema-externalization terms, a methodology for ensuring high schema-fidelity in software models. The insistence on a "ubiquitous language" shared between domain experts and developers is an explicit demand that the software model externalize the domain's conceptual schemas rather than the developer's implementation schemas.
>
> **Boundary Condition:** Unlike a PKB, a software API externalizes schemas for external agents (other developers) rather than for the schema-holder themselves, which means the fidelity target is intersubjective understanding rather than personal cognitive development. The bidirectional enrichment mechanism does not apply in the same way.
>
