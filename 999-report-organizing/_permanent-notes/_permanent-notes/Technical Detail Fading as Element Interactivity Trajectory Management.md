## Core Explanation

> [!evidence] Technical Detail: Fading as Element Interactivity Trajectory Management
> The [[faded-worked-example|faded worked example]] strategy — gradually removing steps from worked examples as the learner develops schemas — is the quintessential *dynamic* application of element interactivity:
>
> 1. **Complete worked example:** Maximum scaffolding → minimum extraneous element interactivity for novice
> 2. **Partially completed example:** Some steps removed → learner must process those steps' element interactivity, but within a scaffolded context that limits total interactivity
> 3. **Problem-solving:** No scaffolding → learner processes full element interactivity using their own schemas
>
> The fading trajectory ideally tracks the learner's schema development — removing scaffolding at the rate at which schemas are compressing element interactivity. Too-fast fading exposes the learner to element interactivity exceeding $WM_{cap}$; too-slow fading creates [[expertise-reversal|expertise reversal]] effects.
>
> **The measurement challenge:** Effective fading requires knowing the learner's current $EI_{eff}$ in real time, which (as Level 3 established) cannot be objectively measured. This creates the adaptive instruction problem that Level 6 (Frontier) will address.
> *— [[cognitive-load-theory-deep-dive-2026-04-12_report]]*
