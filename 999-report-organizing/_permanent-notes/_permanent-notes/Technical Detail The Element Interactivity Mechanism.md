## Core Explanation

> [!evidence] Technical Detail: The Element Interactivity Mechanism
> Element interactivity operates through the following causal chain:
>
> 1. **Learning material contains elements** — discrete units of information that must be processed. These may be facts, concepts, procedures, or relationships.
> 2. **Some elements interact** — understanding element A requires simultaneous processing of elements B, C, and D. The number of simultaneous processing demands defines the interactivity level.
> 3. **Working memory must hold all interacting elements simultaneously** — because understanding depends on processing relationships between elements, not just individual elements in isolation.
> 4. **Working memory's capacity limit constrains how many interacting elements can be processed at once** — roughly 4±1 elements per Cowan's estimate, or approximately 7±2 per Miller's, depending on the definition of "element" and the theoretical model of [[working-memory-capacity]].
> 5. **When element interactivity exceeds working memory capacity, learning fails** — the learner cannot hold enough interacting elements simultaneously to construct the integrative [[schema]] that constitutes understanding.
>
> **Precision:** This chain describes the mechanism at the information-processing level. It does not yet specify what constitutes an "element" (that's Level 3) or how the mechanism produces specific instructional effects (that's Level 4).
> **Dependencies:** Assumes familiarity with [[Baddeley's-Working-Memory-Model]] or Cowan's embedded-processes model.
