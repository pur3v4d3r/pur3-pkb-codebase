## Core Explanation

> [!evidence] Technical Detail: Interactivity Topologies
> **Linear interactivity:** Element A must be processed before Element B, which must be processed before Element C. Each step depends on the previous, but the learner never needs to hold more than 2-3 elements simultaneously (the current step plus its prerequisite). *Example:* Multi-step arithmetic procedures.
>
> **Hierarchical interactivity:** Elements are organized in levels, where higher-level elements depend on multiple lower-level elements. Understanding requires bottom-up construction plus top-down integration. *Example:* Taxonomic classification systems (understanding "mammal" requires simultaneously processing the features that define the category).
>
> **Network interactivity:** Elements are multiply interconnected — A depends on B and C, B depends on A and D, C depends on A and E. Understanding any node requires processing its connections to multiple other nodes, and those nodes themselves require connections to be processed. *Example:* Argument structures where premises support and qualify each other, or systems of simultaneous equations.
>
> **Theoretical implication:** Network interactivity is the most cognitively demanding topology because it does not permit serialization — there is no linear order in which elements can be processed such that each element is understood before it's needed for the next. This is why domains with high network interactivity (law, philosophy, systems biology) are often experienced as qualitatively more difficult than domains with equivalent element counts but linear topology.
>
> **Precision:** This topological analysis is not yet standard in CLT literature. It is an analytical framework that emerges naturally from taking element interactivity seriously at the substructural level.
> *— [[cognitive-load-theory-deep-dive-2026-04-12_report]]*
