## Core Explanation

> [!evidence] Technical Detail: Schema Activation Threshold and Competitive Selection
> Schema activation can be modeled as a threshold competition:
>
> 1. **Input features arrive** (from perceptual processing, text comprehension, problem encoding)
> 2. **Partial activation:** Any schema whose slots are partially matched by arriving features begins to receive activation proportional to the match quality
> 3. **Lateral inhibition:** Partially activated schemas inhibit competing schemas — an architectural feature that drives the system toward a single, decisive interpretation rather than sustained ambiguity
> 4. **Threshold crossing:** The schema with the highest total activation (from both bottom-up input match AND top-down contextual facilitation) crosses the activation threshold first and achieves full instantiation
> 5. **Instantiation stabilization:** Once a schema is instantiated, its top-down predictions actively suppress competing interpretations — the system becomes committed to the instantiated schema and requires substantial counter-evidence to shift
>
> **The priming effect on activation thresholds:** [[priming]] lowers the activation threshold for a schema — the schema requires less bottom-up input match to reach full instantiation when it has received prior context. This explains why the same ambiguous input is interpreted differently by people in different contexts: their recently activated schemas have lowered thresholds and win the competition before alternatives can gather activation.
>
> **Access time implications:** Schema activation is faster for (a) well-automated schemas (lower baseline threshold), (b) primed schemas (threshold lowered by context), and (c) highly typical instances (more features match more slots). This produces the "typicality gradient" in access times — canonical instances are recognized faster than atypical instances.
