# Technical Detail: Schema-Memory Interaction at Encoding and Retrieval

## Core Explanation

> [!evidence] Technical Detail: Schema-Memory Interaction at Encoding and Retrieval
> **At encoding:**
> - Schema-consistent information is processed more efficiently (faster, less effort) but less deeply
> - Schema-inconsistent information generates prediction error, gets allocated more processing, and is often better remembered (the "von Restorff effect" at the schema level)
> - Schema-absent information (information with no schema to assimilate it) is poorly encoded — it floats without organizational anchor
>
> **At retrieval:**
> - Retrieval is cued by schema activation — the schema provides the retrieval structure
> - Default values get substituted for weakly encoded specific values — you "remember" the default when you've forgotten the actual
> - Schema-consistent inferences made at encoding get stored alongside (sometimes instead of) the actual input
> - Over time, episodic memory (what actually happened) fades, while semantic memory (the general schema) persists; recall becomes increasingly schema-reconstructed rather than episodic-retrieved
>
> **The time dimension:** The schema-dominance of memory reconstruction increases with delay. Immediately after reading a story, you can distinguish stated from inferred. Two weeks later, stated and inferred have merged into a single reconstructed narrative shaped predominantly by the schema.
>
> **Precision:** The encoding/retrieval distinction is useful but not absolute — encoding and retrieval are both constructive, and schemas influence both. The retrieval effect (reversion to defaults) is stronger under delay.
> *— [[schema-and-how-they-work-deep-dive-2026-04-08_report]]*
