## Additional Material

> [!protocol] Protocol: Conducting a Recurrent/Non-Recurrent Skill Analysis
> **Purpose:** Classify constituent skills of a complex task into recurrent and non-recurrent categories to determine which 4C/ID components serve each skill.
>
> **Steps:**
> 1. **Identify the complex skill** and its performance context.
> 2. **Decompose into constituent skills** — list all identifiable sub-skills required for competent performance.
> 3. **For each constituent skill, ask:** "Does this skill's execution vary meaningfully across different problem instances within the same complexity level?"
>    - **YES → Non-recurrent.** This skill requires reasoning, judgment, or adaptation to context. It will be served by learning tasks (for practice) and supportive information (for schema construction).
>    - **NO → Recurrent.** This skill is performed the same way regardless of context. It will be served by learning tasks (for contextualized practice), procedural information (for initial guidance), and potentially part-task practice (for automation).
> 4. **Validate classification** by testing edge cases: Can you write a fixed procedure that would always produce correct performance? If yes → recurrent. If the procedure requires if-then branching based on contextual assessment → likely non-recurrent (the assessment is non-recurrent even if the subsequent actions are recurrent).
> 5. **Document in a skill hierarchy** showing recurrent (R) and non-recurrent (NR) labels for each constituent skill.
> *— [[four-component-instructional-design-model-4cid-foundational-report-2026-04-18]]*
