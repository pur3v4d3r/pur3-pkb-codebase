## Core Explanation

> [!evidence] Software Architecture and Information Architecture
> The structural parallels between PKM design and software architecture are striking and non-coincidental — both are fundamentally exercises in information architecture, concerned with how complex information is decomposed, organized, connected, and accessed. The [[Zettelkasten-Method|Zettelkasten]] principle of one-idea-per-note mirrors the software engineering principle of the [[Single-Responsibility-Principle|single responsibility principle]]: each module (or note) should have one reason to exist and one reason to change. The link-based organizational architecture mirrors the principle of loose coupling with high cohesion: notes (modules) are internally coherent and externally connected through well-defined interfaces (links with semantic context). The [[schema-theory-and-knowledge-organization|schema construction]] process — building organized knowledge structures from individual concepts — mirrors the refactoring process in software engineering — reorganizing code into coherent abstractions as understanding of the problem domain deepens. The common substrate is cognitive: both PKM design and software architecture are constrained by the same working memory limitations and served by the same associative memory dynamics.
>
> **Boundary condition:** Software systems have formal specification and testing capabilities that knowledge bases lack; the "correctness" of a knowledge structure is ultimately a judgment, not a computable property.
>
