## 🧭 Hints

> [!tip]- Hint 1 — The three-type distinction is load-bearing
> Cognitive load theory (Sweller) distinguishes **intrinsic** (inherent to the material), **extraneous** (imposed by how it's presented), and **germane** (used for schema construction) load. A state-of-the-concept that omits this distinction is incomplete. Most poor instruction increases *extraneous* load — that's the practical hook.

> [!tip]- Hint 2 — Counter-example clue
> "Difficulty" is not the same as "cognitive load." A problem can be difficult because it requires sustained effort (high *intrinsic* load) without being badly designed (low *extraneous* load). Or a problem can be easy intrinsically but high in extraneous load because of how it's presented. The counter-example should exploit this distinction.

## ✅ Solution Sketch

> [!example]- Solution Sketch — Key Analytical Moves
>
> **State:** Cognitive load is the amount of [[Working Memory]] capacity consumed by a task, comprising the intrinsic complexity of the material, the extraneous demands imposed by how the material is presented, and the germane processing devoted to constructing durable [[Schema|schemas]].
>
> **Elaborate:**
> Cognitive Load Theory (Sweller, 1988) treats working memory as a severely limited resource — roughly 4±1 chunks at once, holding for ~20 seconds without rehearsal — and explains learning difficulty as a function of how the demands on this resource decompose. **Intrinsic load** comes from the material itself: solving a single-variable equation has lower intrinsic load than a system of three equations. **Extraneous load** comes from presentation choices that are not necessary to the learning: split-attention designs, redundant text, poor signaling. **Germane load** is the productive consumption of working memory devoted to building schemas in long-term memory — the load you *want* learners to experience.
>
> What the concept excludes: motivation, attention, emotion, prior knowledge level (these affect load *experience* but are not load itself).
>
> The concept matters because almost all evidence-based instructional design — worked examples, completion problems, signaling, redundancy elimination — derives from reducing extraneous load and freeing capacity for germane processing.
>
> **Exemplify 1 (learning/familiar):**
> A geometry textbook prints a proof on page 12 and the labeled diagram on page 13. To follow the proof, the student must hold the diagram in working memory while reading the proof, or flip between pages. This is **extraneous load** — the *learning content* is the proof; the *split-attention design* imposes additional load that adds nothing to schema construction. The same proof with diagram + text integrated on one page has lower extraneous load and produces faster, deeper learning.
>
> **Exemplify 2 (transfer domain — software UX):**
> A web form asks the user to enter their date of birth, with three separate dropdowns (month name in one, day number in another, year in a third). The user must hold the date in working memory while navigating three controls and translating "March" to a position in an alphabetical list (which itself adds processing). The same form with a single ISO date field has lower extraneous load. The task (enter your DOB) is unchanged; the *design* changes the load.
>
> **Counter-example:**
> A graduate-level algebraic topology textbook is genuinely difficult; reading it requires hours of effort per page. This is **high intrinsic load** — inherent to the material, not a design flaw — and is **not** what cognitive load theory recommends reducing. Confusing "the material is hard" with "the design imposes extraneous load" is a common misapplication of the theory. CLT does not recommend dumbing down content; it recommends not adding *unnecessary* load on top of the inherent complexity.
>
> **Illustrate (analogy):**
> Working memory is like a small kitchen counter with limited surface area. Intrinsic load is the food you're actually cooking — the recipe determines how much counter space it needs. Extraneous load is unnecessary clutter on the counter (dirty dishes, junk mail, a misplaced cookbook) that takes space without contributing to the meal. Germane load is the bowl in which you're actively combining ingredients — productive use of counter space. The cook's skill is not reducing the recipe; it is removing the clutter so the productive bowl has room.
>
> **Mastery self-check:**
> - Teach to a 12-year-old? ✅ (use the kitchen-counter analogy).
> - Distinguish from: [[Extraneous Load]] (subtype, not the whole concept); "difficulty" (not equivalent — see counter-example); "[[Mental Effort]]" (related but distinct — effort is what you spend, load is what is demanded).
> - Transfer? ✅ (the software UX example was a non-learning domain).
> - Paul-Elder element? Primarily **Concepts (1.5)** — CLT is itself a conceptual framework — and **Implications (1.7)** because it generates concrete design prescriptions.
